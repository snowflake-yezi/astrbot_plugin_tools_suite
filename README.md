# AstrBot 工具集插件

将实时金价查询、群聊昵称批量 @、QQ 合并转发展开与查重整合为一个插件。工具按当前群或私聊会话隔离，默认全部关闭。

## 安装

插件要求 AstrBot `>=4.9.2,<5` 和 Python 3.12，平台元数据声明支持 `aiocqhttp`，适用于通过 NapCat 接入 QQ 的 AstrBot 实例。

将 `astrbot_plugin_tool_suite` 放入 AstrBot 的 `data/plugins/` 目录并重启 AstrBot。AstrBot 会根据 `requirements.txt` 安装运行依赖。请停用原来的 `gold_price` 和 `nickname_at` 插件，避免相同指令被重复处理。

## 开关与管理

插件内所有指令均可直接发送文本触发，不依赖 `/` 命令前缀。

| 指令 | 功能 |
| --- | --- |
| `工具开` | 开启当前会话可用的金价、昵称和聊天记录工具；昵称仅支持群聊 |
| `工具关` | 关闭当前会话的全部工具，保留已有数据 |
| `金价开` / `金价关` | 开启或关闭当前会话的金价工具 |
| `昵称开` / `昵称关` | 单独开启或关闭当前群的昵称工具 |
| `聊天记录开` / `聊天记录关` | 开启或关闭合并转发查重提醒与完全重复撤回 |
| `聊天记录增强开` / `聊天记录增强关` | 控制嵌套记录的原内容平铺重发；开启时同步开启聊天记录工具 |
| `聊天记录查重天数 N` | 设置当前会话查重范围，支持 1-365 天，默认 2 天 |
| `聊天记录状态` | 查看开关、查重天数和范围内记录数 |
| `工具状态` | 查看当前会话的全部工具状态 |
| `工具帮助` | 查看指令帮助 |

开关和状态指令始终可用。`工具开` 会开启当前会话可用的金价、昵称和聊天记录功能，不主动开启增强；`工具关` 关闭全部功能（包括增强），已有数据保留。增强默认关闭，关闭增强不影响基础查重提醒和完全重复撤回；关闭聊天记录工具则暂停包括平铺在内的全部聊天记录处理。

金价或昵称工具关闭时，查询、走势图、昵称查询和绑定消息会被静默忽略；用户主动发送开关指令时仍会收到操作结果。

## 金价工具

| 指令 | 功能 |
| --- | --- |
| `金价` | 查询实时金价（人民币/克） |
| `金价走势` | 查看最近 15 个交易日的柱状折线混合图 |
| `gold` / `goldk` | 兼容的英文查询指令 |
| `金价K线` | 兼容原插件的走势图指令 |

行情源依次为 GoldPrice.org 加 USD/CNY 汇率、上海黄金交易所和新浪财经，查询结果缓存 90 秒。自动测试只验证源回退、缓存和结果契约，不访问真实行情站。

走势图历史数据优先使用东方财富，失败时自动改用上海黄金交易所官方日线。成功结果缓存 5 分钟，若两路接口临时均不可用，还可使用 24 小时内最近一次成功数据；只有两路数据源和故障缓存都不可用时才返回获取失败。

走势图折线表示每日收盘价，红柱表示收盘不低于开盘，绿柱表示收盘低于开盘。字体优先使用系统中文字体，否则使用插件内置的精简 Noto Sans SC。生成图片位于 AstrBot 的 `data/temp/tool_suite/gold_trend.png`。

## 昵称工具

昵称功能只在群聊中可用，并按群保存数据。

| 指令 | 功能 |
| --- | --- |
| `@某人 昵称` | 查询该用户已绑定的昵称 |
| `@某人 昵称 新昵称` | 给该用户绑定一个昵称 |
| `at昵称 待发送消息` | @ 当前群内绑定该昵称的所有用户并附带消息 |

一个用户可绑定多个昵称，一个昵称也可绑定多个用户。匹配时长昵称优先。

## 聊天记录查重与提醒

该功能只处理 QQ/NapCat 合并转发消息，按群或私聊独立查重。普通文字、图片等独立消息以及机器人自身发送的消息不会进入查重库。开启后，插件递归识别合并转发内容，不让该条记录触发默认 LLM 回复。增强开关仅控制嵌套记录平铺重发，不改变以下查重提醒与撤回规则。

| 判断结果 | 行为 |
| --- | --- |
| 没有重复内容 | 入库，不发送提示文字；增强开启时平铺重发嵌套记录 |
| 部分叶子消息与历史重复 | 引用最近命中的历史原消息，@ 本次发送者，并回复 `咦，好熟悉的感觉，里面有部分内容已经有人发过一次啦` |
| 整份记录完全重复 | 尝试撤回本次消息，同时引用命中的历史原消息、@ 本次发送者并发送 `assets/duplicate_forward.jpg` |
| 展开失败、识别失败、空记录或超出限制 | 静默，不写入查重库 |

完全重复时，撤回失败不会阻止提醒。提醒图缺失、无法读取或发送失败时，使用文字 `咦，这份聊天记录已经有人发过啦，期待你下次带来新鲜的好东西~`，仍引用历史并 @ 本次发送者；撤回和图片失败原因仅记录日志。

部分重复命中多份历史时，选择入库时间最近的一份；完全重复优先于部分重复。引用目标是历史原消息，不是本次重复消息。没有消息 ID 的历史记录仍可用于查重，但提醒会省略引用，只 @ 本次发送者，不伪造历史消息 ID。

历史保存原消息 ID、入库时间和内容指纹。完全重复不会覆盖这些信息或保存将被撤回的本次消息；查重期限以原记录入库时间计算，后续部分重复判断仍以原消息的叶子分组为准。历史消息在 QQ 中被删除或过期后，平台可能无法展示引用。

### 嵌套记录平铺

增强开启时，无重复和部分重复的嵌套记录都会重组为最外层的一组 Node，让每份记录只需打开一层即可查看内容。保留原始消息内容、先后顺序、可取得的发送者信息和时间，也保留重复出现的消息；不摘要、不改写、不筛除重复内容。单层记录不重发，完全重复记录只执行撤回与提醒。

每批最多 100 个节点，超出后按原顺序拆成多份发送，例如 205 个节点发成 100、100、5 三份。100 是插件采用的批次上限，不代表 NapCat 对所有媒体内容都保证可发。发送失败时停止后续批次、只记录日志，不撤回原始记录；部分重复提醒仍会发送。媒体缓存过期、平台限制或不可重发的组件可能导致发送失败。

内层转发支持转发 ID 和 NapCat 的 `forward.data.content` 内联内容。单份记录最多 16 层真实转发、256 层协议结构、5000 条叶子消息和 10000 个组件；超过限制或拉取失败时不会写入查重库。

整份内容指纹忽略容器 ID、节点分组、节点时间和转发者，保留组件顺序及重复次数；部分重复按完整叶子消息判断，不会仅因共享一个文本或媒体组件就认定重复。媒体优先使用平台提供的 MD5/SHA，其次使用媒体 ID 或清理临时参数后的地址；插件不会下载媒体，也不执行 OCR、视频识别或语音转写。

历史引用、@ 和提醒通过 AstrBot 官方消息组件发送。`get_forward_msg` 先尝试 NapCat 的 `message_id`，再回退 OneBot 11 的 `id`；撤回使用 `delete_msg(message_id=...)`，旧版 `bot.api.call_action` 仅作兼容回退。群聊撤回要求机器人具有足够权限，且 QQ 权限层级仍然生效。

## 数据

正式状态文件位于 AstrBot 的 `data/plugin_data/tool_suite/tool_suite.json`。若插件目录内只存在旧路径 `data/tool_suite.json`，首次加载会先原子写入正式路径，确认成功后再删除旧文件。

关闭工具不会删除数据。过期记录会在后续查重时清理；全部会话共享约 16 MiB 的序列化查重历史预算，超出后按时间淘汰最旧记录，只影响查重历史，不影响开关和昵称。

指纹版本是持久化契约。当前版本为 `3`；版本 `2` 的完整记录可继续用于整份或部分重复判断。更早且无法可靠迁移的指纹会被清除，其他设置保持不变。历史中的 `message_id` 可以缺失，读取时视为无法引用的记录。

## 模块结构

| 路径 | 责任 |
| --- | --- |
| `main.py` | AstrBot `Star` 组合根及装饰器入口，不实现功能策略 |
| `core/` | 路径配置、共享数据模型、事件取值和原子 JSON 状态存储 |
| `features/gold/` | 行情源、缓存与格式化、图表渲染、金价 handler |
| `features/nickname/` | 昵称领域规则和 AstrBot 消息 handler |
| `features/forward/` | 转发解析与指纹、查重历史、OneBot 网关、应用 handler |
| `tests/` | 纯领域测试、功能 handler 测试及 AstrBot/OneBot 契约测试 |

AstrBot 会按装饰函数的模块路径绑定插件实例，因此被装饰的入口方法必须保留在 `ToolSuitePlugin` 上；功能模块不自行注册第二套 handler。

## 开发验证

使用 `uv` 建立项目内 Python 3.12 环境：

```bash
uv venv .venv --python 3.12
uv pip install --python .venv -r requirements-dev.txt
.venv/Scripts/python.exe -m pytest -q
.venv/Scripts/ruff.exe check .
.venv/Scripts/ruff.exe format --check .
```

macOS/Linux 将 `.venv/Scripts/` 替换为 `.venv/bin/`。完整测试发现需要安装开发依赖；异步测试使用标准库 `unittest.IsolatedAsyncioTestCase`，不依赖 `pytest-asyncio`。

完整测试使用独立 `ASTRBOT_ROOT`，覆盖：

- 真实插件包导入、handler 注册、异步生成器入口和 `AIOCQHTTP` 平台过滤器。
- 历史引用、@、文字和提醒图到群聊及私聊 OneBot 消息的序列化。
- NapCat `get_forward_msg` 参数回退、群聊与私聊平铺分批、动作失败与 `delete_msg` 撤回回退。
- 无重复时无提示、识别失败时静默、嵌套平铺保留原文与重复项、最近历史引用及撤回/图片失败回退。
- 正式数据目录及旧状态迁移、三个功能 handler、查重限制与历史预算。
- Matplotlib `Agg` 渲染，并以 Pillow 检查输出 PNG 尺寸和非空像素。

自动测试不连接真实 QQ。发布前仍应在目标 AstrBot + NapCat 实例验证：群聊与私聊转发拉取、内联及 ID 嵌套记录、平铺媒体可用性和超过 100 个节点的分批展示、历史引用和 @ 展示、提醒图发送、机器人权限不足时的撤回日志，以及三个真实金价源的当前响应格式。
