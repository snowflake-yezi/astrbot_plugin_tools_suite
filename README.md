
# AstrBot 工具集插件

将实时金价查询、群聊昵称批量 @、QQ 合并转发展开与查重整合为一个插件。工具按当前群或私聊会话隔离，所有工具默认关闭。

## 安装

将 `astrbot_plugin_tool_suite` 放入 AstrBot 的 `data/plugins/` 目录并重启 AstrBot。依赖由 AstrBot 根据 `requirements.txt` 安装，也可以手动执行：

```bash
pip install -r requirements.txt
```

请停用原来的 `gold_price` 和 `nickname_at` 插件，避免相同指令被重复处理。

## 开关与管理

插件内所有指令均可直接发送文本触发，不依赖 `/` 命令前缀。

| 指令 | 功能 |
|------|------|
| `工具开` | 开启当前会话可用的金价、昵称和聊天记录工具；昵称仅支持群聊 |
| `工具关` | 关闭当前会话的全部工具，保留已有数据 |
| `金价开` / `金价关` | 开启或关闭当前会话的金价工具 |
| `昵称开` / `昵称关` | 单独开启或关闭当前群的昵称工具 |
| `聊天记录开` / `聊天记录关` | 单独开启或关闭合并转发展开与查重 |
| `聊天记录增强开` / `聊天记录增强关` | 单独开启或关闭平铺重发、内容去重和完全重复撤回 |
| `聊天记录查重天数 N` | 设置当前会话查重范围，支持 1-365 天，默认 2 天 |
| `聊天记录状态` | 查看开关、查重天数和范围内记录数 |
| `工具状态` | 查看当前会话的全部工具状态 |
| `工具帮助` | 查看指令帮助 |

开关指令和状态指令始终可用。首次使用或新会话首次出现时，所有工具均为关闭状态。`聊天记录增强开` 会同步开启基础聊天记录查重；`聊天记录增强关` 只关闭增强动作，原来的展开与查重仍保持开启。`工具开` 不会自动开启聊天记录增强，`工具关` 会将基础与增强功能一并关闭。

金价或昵称工具关闭时，相关查询、走势图、昵称查询和绑定消息会被静默忽略，不再回复“请先开启”提示。用户主动发送开关指令时，机器人仍会回复操作结果。

## 金价工具

| 指令 | 功能 |
|------|------|
| `金价` | 查询实时金价（人民币/克） |
| `金价走势` | 查看最近 15 个交易日的柱状折线混合图 |
| `gold` / `goldk` | 兼容的英文查询指令 |
| `金价K线` | 兼容原插件的走势图指令 |

数据源按顺序使用 GoldPrice.org 与 USD/CNY 汇率、上海黄金交易所、新浪财经；结果缓存 90 秒。

走势图中的折线表示每日收盘价，红柱表示当日收盘高于或等于开盘，绿柱表示当日收盘低于开盘。

走势图历史数据优先使用东方财富，失败时自动改用上海黄金交易所官方日线。成功结果缓存 5 分钟，若两路接口临时均不可用，还可使用 24 小时内最近一次成功数据；只有两路数据源和故障缓存都不可用时才返回获取失败。

走势图优先使用系统中文字体，未安装中文字体时自动使用插件内置的精简 Noto Sans SC 字体。日期轴最多展示 8 个均匀分布的日期，高低点标注会保留足够的上下边距。

## 昵称工具

昵称功能只在群聊中可用，并按群保存数据。

| 指令 | 功能 |
|------|------|
| `@某人 昵称` | 查询该用户已绑定的昵称 |
| `@某人 昵称 新昵称` | 给该用户绑定一个昵称 |
| `at昵称 待发送消息` | @ 当前群内绑定该昵称的所有用户并附带消息 |

一个用户可绑定多个昵称，一个昵称也可绑定多个用户。匹配时长昵称优先。

## 聊天记录展开与查重

该功能只处理 QQ/NapCat 合并转发消息，单独发送的普通文字、图片和其他消息不会进入查重库。只开启基础功能时，插件会递归拉取并展开其中的嵌套合并转发，再引用回复原消息：

| 判断结果 | 回复内容 |
|----------|----------|
| 最近 N 天没有相同节点内容 | `咪~让我看看，你又发出来什么好东西` |
| 部分展开节点与历史聊天记录重复 | `咦，好熟悉的感觉，里面有部分内容已经有人发过一次啦` |
| 整份展开后的聊天记录已经出现过 | 引用该条合并转发并发送插件内置的 `news.jpg` 提示图 |

默认查重最近 2 天，可以执行：

```text
聊天记录开
聊天记录查重天数 7
聊天记录状态
聊天记录关
```

需要自动平铺、去重重发和撤回完全重复记录时，另行执行 `聊天记录增强开`。增强功能默认关闭，三种判断结果对应的动作如下：

| 判断结果 | 增强动作 |
|----------|----------|
| 最新消息 | 只有包含第二层合并转发时才会递归铺平并重发；原本已经是一层的记录不再重复发送 |
| 部分重复 | 铺平后删除历史中已出现的相同叶子消息以及本次记录内部重复消息，再发送剩余内容 |
| 完全重复 | 直接撤回用户发送的原合并转发，不发送 `news.jpg`，也不重发内容 |

插件会记录当前聊天记录的最大合并转发层数，外层记录计为第 1 层，只有其中再次出现 `Forward` 或 `Nodes` 容器才属于嵌套记录。部分重复仍需执行去重重发，因此不受“最新消息必须嵌套”的限制。

增强功能处理合并转发时完全静默：不发送查重结果、`news.jpg`、成功说明或失败提示，只执行展开去重、平铺重发和完全重复撤回；失败原因仍会写入机器人日志。未开启增强时，基础功能的查重结果、`news.jpg` 和展开失败提示全部保留。基础 `聊天记录开`、`聊天记录关` 的回复与行为不受增强功能调整影响。

平铺发送和撤回依赖 QQ/NapCat 的 OneBot 动作接口。单次平铺最多发送 100 个节点，超过时按原顺序分批发送；最多仍受单份记录 5000 条叶子消息限制。撤回优先使用 AstrBot 官方的 `event.bot.api.call_action` 接口，并兼容直接 `call_action`。群聊中机器人需要管理员权限；受 QQ 权限层级限制，群管理员机器人不能撤回群主或其他管理员发送的消息。

查重按当前群或私聊会话隔离。内容指纹忽略转发容器 ID、节点分组方式、节点发送时间和转发者，但保留文字与媒体的出现顺序和重复次数；因此相同内容被重新分组转发时仍能识别，内容顺序不同则不会判为整份完全重复。内层转发既支持新的转发 ID，也支持 NapCat 直接放在 `forward.data.content` 中的内联消息。

从 `1.1.5` 开始，展开指纹带有算法版本；`1.2.0` 为支持叶子消息去重将当前版本升级为 `3`。版本 `2` 已使用相同的完全展开指纹，升级时会保留其历史记录；这些旧记录没有叶子哈希，因此在过期前仍可判断整份或部分重复，但增强重发无法按旧记录过滤叶子节点。只有版本 `2` 以前无法可靠迁移的指纹会被清除，开关、昵称和查重天数不受影响。整份完全重复同时按指纹和展开后的组件序列判断，节点重新分组不影响结果。

合并转发内部的图片、视频、语音和文件会参与查重。插件优先使用平台提供的 MD5/SHA 摘要，其次使用媒体 ID 或去除临时参数后的文件位置；不会下载文件，也不执行图片 OCR、视频画面识别或语音转文字。因此，只要 QQ/NapCat 对同一媒体返回稳定标识，就能检出重复；平台未返回稳定标识时只能按现有元数据比较。

增强平铺重发媒体时，插件会优先使用平台返回的有效 `url`，并将 NapCat 返回的 Linux 或 Windows 裸绝对路径转换为 `file://` URI，同时清理首尾空白并编码路径中的空格。该转换只作用于 OneBot 重发载荷，不改变查重指纹；如果 NapCat 本地缓存文件已经被删除，即使 URI 格式正确，平台仍可能拒绝发送。

嵌套深度最多 16 层，单份记录最多展开 5000 条叶子消息和 10000 个消息组件；超过限制或平台无法拉取转发内容时不会写入查重库。

## 数据

开关、昵称和聊天记录查重指纹保存在 `data/tool_suite.json`。关闭工具不会删除数据；超过当前查重天数的聊天记录会在后续查重时清理。全部会话共享约 16 MiB 的查重历史预算，超出后按记录时间从旧到新淘汰，只清理查重历史，不影响开关和昵称。

- Python 3.10+
- `aiohttp`
- `matplotlib`
- `numpy`
- `pillow`
